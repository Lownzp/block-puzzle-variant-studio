# 识别架构改造方案（托盘优先重构）

> 本文档是识别算法在 12 次实验进入平台期后的一次全局复盘与方向调整，用于统一后续改造思路，避免继续在事件后处理层做无收益的局部调参。它承接《视频动作识别优化实施计划》，聚焦"接下来应该改什么、按什么顺序改"。

## 0. 通俗版（先看这段）

这个软件的任务：看一段方块消除游戏录屏，自动认出玩家每一步——从哪个槽拿了什么形状的方块、放到哪、有没有消除，然后换皮批量生成变体视频。

现在卡住的根本原因，一个比喻：

> 想知道别人往锅里放了什么菜，现在的做法是**盯着锅里最后剩什么来倒推**。可有些菜一下锅就化了，看不出原样，所以老猜错。

代码现在就是靠"棋盘前后的变化"来猜方块形状。但方块一落下经常立刻被消除，棋盘上看到的已经不是方块本来的样子，形状自然认不准。而方块在被拿走之前，本来好端端摆在下面的槽里、形状清清楚楚——**应该直接看槽里的方块，而不是猜棋盘变化。**

为什么试了十几个优化都没用：过去所有尝试都是在"猜完之后"修修补补，没动"一开始就看错地方"这个根子；而且只用 2 条互相矛盾的视频反复测（一条嫌松、一条嫌紧），永远按下葫芦浮起瓢。

改造就三件事：**① 换准尺子（多几条视频测）② 换个地方看（读槽里的方块，不猜棋盘）③ 别硬追全自动（机器搞定有把握的，没把握的标出来让人点一下）。**

## 1. 背景：平台期是怎么形成的

截至 `66c153f`，围绕常规彩色方块路径已做 8 类实验：

| 实验开关 | 性质 | 结果 |
|---|---|---|
| `temporal_candidate_cache` | 后处理·缓存 | 无变化（仅诊断） |
| `cell_temporal_voting` | 后处理·过滤 | 负向（增假动作） |
| `fsm_event_constraints` | 后处理·过滤 | 负向（杀召回） |
| `stable_state_scoring` | 后处理·过滤 | 负向（杀召回） |
| `single_frame_shadow_refine` | 单帧·refine | 无变化 |
| `sequence_repair_clear_v1` | 后处理·修补 | 无变化 |
| `sequence_repair_shape_target_v1` | 后处理·修补 | 无变化 |
| `sequence_candidate_gap_fill_v1` | 后处理·补漏 | 负向（增假动作） |
| `sequence_candidate_rerank_v1` | 后处理·联合重评分 | +1 个动作（DEV-008） |

规律非常清晰：**过滤类一律杀召回，修补类一律无效或只挪动 1 个动作。** 最新的 `sequence_candidate_rerank_v1` 是第一个推动指标的实验（semantic/shape/clear 各 +2.22pp），但：

- 幅度 = 在 2 条视频上移动 1 个动作，属噪声量级；
- `recall / missed` 完全没动（仍漏 7 个）；
- 它赢在 `shape + target + clear` 联合评分 + "复用同视频其他动作的连通形状当候选词表"（`variant_bridge.py:sequence_candidate_rerank` 的 `event_shape_catalog`）——这实际上是在**绕弯承认"真形状是干净的托盘形状，而不是被消除污染的棋盘差分"**。

**结论：最好的后处理，也只能在"已诞生的动作"上把形状/消除修对，对没诞生的动作无能为力。** 瓶颈不在后处理层。

## 2. 根因诊断（三件事叠加）

### 2.1 测量不可信

- 长期只在 `DEV-004 + DEV-008` 两条上调参，而这两条互相对撞：DEV-004（30 步、precision 100%）一放松就碎片化，DEV-008（召回老大难）需要更多候选。**一个全局标量阈值想同时服务两条反向样本，梯度恒为零。**
- `truth_benchmark.py` 的语义准确率（slot/shape/target/clear）只在**配对成功的动作**上统计（见 `evaluate_task` 里 `matched`）。一旦候选生成漏检，后续预测整体错位、连环误配，会把本来认对的形状也算成错。**所以现在看到的 shape≈88% 里混着"漏检导致的配对错位"，不全是形状识别错。**

### 2.2 架构方向错：棋盘优先，信息中途被销毁

真实管线（`timeline_analyzer.py:build_timeline`）：

```
帧 → 单格占用（离散化） → 稳定态合并 → 棋盘差分(added/removed) → 规则模拟
                                          ↑
                     动作是否"存在"，取决于棋盘是否形成一个可分辨的独立稳定态
```

两个致命点：

1. **动作的"诞生"绑定在棋盘占用态上。** 一步若没形成独立稳定态（DEV-010 木纹样本笔记原话："占用态没有形成独立稳定状态导致候选缺失"；落子即消同理），这个动作**根本不会被生成**。补漏只能靠"棋盘凭空多格子"来猜，所以 `gap_fill` 一开就是假动作。**没诞生的东西，任何下游救不回来——这是 recall 天花板的来源。**
2. **shape 用棋盘差分为主、托盘为兜底。** `build_timeline` 内 `board_delta_shape`（约 `timeline_analyzer.py:3377`）是主证据；托盘形状仅在强证据下才被采纳。更糟的是 `source_has_extra_edge_cells` 分支（约 `timeline_analyzer.py:3508-3534`）会**主动丢弃托盘真值、改用被 clear 污染的棋盘差分**（理由串 `source_slot_edge_cells_rejected_by_board_delta`）。**落子即消时，棋盘差分 = 被消掉一部分后的残影 ≠ 真实方块。** 这是在信息熵最高的点做了最差的选择——shape/slot/clear 天花板的来源。

### 2.3 目标函数错：在人机协同系统里追全自动精度

系统从设计上就是人机协同：《验收标准》第 6 条"有歧义必须停止并标记待复核"、实施计划 §8 多解规则、以及整套 `annotation-studio` 复核界面。**在这种系统里，真正该最小化的不是"机器全自动认对率"，而是"把一条视频修到完全正确所需的人工编辑次数"，且前提是绝不静默输出错误动作。**

- 漏检是**廉价**的——只要暴露成"此处有缺口，待复核"，人补一下即可。
- 静默误接（把低置信形状当高置信自动接受）是**昂贵且危险**的。

过去的调参在无差别地追求全自动精度，等于用错了目标函数。

## 3. 改造总纲：一条主线，三步

主线：**把证据架构从"棋盘优先"改为"托盘优先"，把目标函数从"全自动精度"改为"人工修正成本"，并先把测量尺子换准。** 三步的顺序是刻意的——第 0 步不做，后面全是自欺。

### 3.1 第 0 步：先修测量（前置条件，低风险）

- **启用实施计划 §16 已设计但一直未用的 12 条调优集**，冻结 12 条封存集；停止只在 DEV-004+008 上调参。
- **把"检测"与"识别"拆开报告**：在"动作数正确"的条件下再统计 shape/slot/target/clear（指标定义见实施计划 §19），从根本上区分"没检出"与"认错了"。
- **按场景分组出分**（录屏 / 快节奏 / 连消 / 低分辨率 / 3D 材质），避免简单样本掩盖难样本。

产出：第一份**可信基线**。在此之前，任何改动的收益都无法与噪声区分。

> 落地状态（2026-07-23）：`truth_benchmark` 已实现检测/识别解耦与按场景分组——每条视频新增 `actionCountExact`（动作数是否完全正确）、`matchedAligned` 与 `*Aligned` 系列（仅在配对落入真值动作窗口的子集上统计识别指标，剔除漏检导致的配对错位噪声）；汇总新增 `actionCountExactRate` 与按场景的 `byScene` 分组。单测见 `tests/test_truth_benchmark.py`。**待办**：接入实施计划 §16 的 12 条调优集真值目录，跑出首份可信基线；场景标签需在真值文档写入 `scene`/`scenario`/`category`/`family` 之一，否则归入 `unlabeled`。

### 3.2 第 1 步：主干重构——证据层级反转为"托盘优先"

这是唯一值得投入的技术改造，且**一次重构同时打击 shape/slot/clear 和 recall 两个瓶颈**，因为它们本质是同一个架构错误。

改造要点：

1. **托盘 = shape + sourceSlot 的第一证据。** 三槽静止填满时，多帧投票快照每个槽的精确形状——干净、不受消除污染、槽位几何固定。把 `build_timeline` 中 `board_delta_shape` 主导、托盘兜底的优先级**倒过来**：托盘强证据为主，棋盘差分仅在托盘缺失时兜底；删除/降级 `source_has_extra_edge_cells` 那种"用棋盘差分覆盖托盘真值"的逻辑。
2. **槽位生命周期（填充 → 清空 → 下一轮刷新）= 动作的独立触发器。** 一个槽清空即是一个动作，**哪怕棋盘没形成干净的新稳定态**（正是落子即消、木纹噪声这类漏检的根因）。这把 recall 从"绑定棋盘占用态"里解放出来。
3. **棋盘只保留两个低维职责：落点(target) + 消除判定(clear)**，且都用规则模拟精确复现来验收。错误面从"猜整个二维形状"缩小到"给已知形状找落点 + 判一个布尔/整行列集合"，小一个数量级。

**关键降风险点：机器已经全在了。** 托盘链路的函数均已存在，只是被接成了副证据：

- `timeline_analyzer.py:_bottom_groups`（约 1143）——三槽形状提取
- `timeline_analyzer.py:_detect_source_slot_pickups`（约 1275）——槽位拾取检测
- `timeline_analyzer.py:_pickup_piece_shape`（约 1615）——拾取形状恢复
- `timeline_analyzer.py:_pickup_visual_evidence`（约 2054）——拾取视觉证据
- `timeline_analyzer.py:_source_slot_material_consensus`（约 2008）——槽位形状多帧共识

**这是"重新接线"，不是"从零造轮子"**，投入产出比远高于再加一个后处理开关。

### 3.3 第 2 步：重定义目标函数——优化人工修正成本

基础设施已建好（`annotation-studio` + 版本化真值 + 规则复现闸门），把目标函数落实为分诊流程：

- **每个分量（slot/shape/target/clear）输出校准置信度。**
- **自动接受的唯一闸门：规则模拟能精确复现下一稳定棋盘。** 满足才自动确认；否则全部进复核队列，并按"对下游影响大小"排序。这条闸门（放进去必须精确复现棋盘）已经存在，它保证了"永不臆造"。
- **交付指标改为"自动确认且正确的动作占比"与"每条视频到完全正确所需人工编辑次数"。** 产品终点是变体视频，而一条确认无误的脚本 → 无限变体；因此识别的每一分提升都用"省下多少复核分钟"来衡量，复核回路则是让你在识别尚未完美时就能交付的安全网。

### 3.4 保留手段（按证据触发，非现在就上）：定点小模型

若第 0+1 步在 12 条集上跑完后，残差瓶颈确认落在**感知原语**上——单格占用（3D / 木纹 / 低分辨率下阈值失效）与同色相连块的槽内拆格——那才是小模型该上的地方（分类问题，手调阈值本就会平台化；项目已有 `models/cell_occupancy_model.json` 这一学习模型）。

原则：

- **只替换两个感知原语**：单格占用分类器、槽内形状分类器。
- **保留确定性规则模拟主干与"精确复现"验收闸门。**
- **绝不上端到端动作模型**——那会毁掉"不臆造、可精确回放"这一核心保证。
- **在第 1 步证明感知是残差瓶颈之前，不要动这块。**

## 4. 执行顺序与里程碑

1. **换尺子**：`truth_benchmark` 增加"检测/识别解耦 + 按场景分组"报表；用 12 条调优集跑当前默认路径，产出可信基线。（里程碑：拿到按场景、按检测/识别拆分的真实瓶颈分布）
2. **通托盘链路**：读透 §3.2 列出的 5 个函数，评估把托盘提升为主证据的改造范围与回归风险。（里程碑：形成最小重构切口，DEV-004 不碎片化）
3. **反转证据层级**：实现托盘优先 + 槽位生命周期触发；棋盘退居 target/clear。（里程碑：调优集上 shape/slot/clear/recall 同步改善，且规则复现闸门 100% 拦住不一致动作）
4. **分诊上线**：校准置信度 + 复核队列排序；交付指标切到"人工修正成本"。（里程碑：单条视频人工编辑次数显著下降）
5. **按需上小模型**：仅当第 3 步显示感知为残差瓶颈时启动。

## 5. 风险与回退

- **托盘在拖拽/拾取瞬间被遮挡** → 只在"三槽静止填满"的稳定帧多帧投票快照，不取运动帧（`_bottom_groups` + 多帧恢复已具备该能力）。
- **同色相连块在托盘内也难拆格** → 是同一个难题，但托盘版更干净（无消除污染、槽几何固定、拾取前可多帧投票），严格易于"消除后的棋盘差分"；拆格仍歧义时转复核，成本低。
- **重构回归 DEV-004（碎片化）** → 所有自动接受一律经规则复现闸门；DEV-004 作为强制回归样本，任一步碎片化即回退该切口。
- **改动混入默认路径造成整体退化** → 沿用现有纪律：独立开关、独立测试、先过 12 条调优集再谈进入默认路径。

## 6. 明确不再做的事

- 停止"在 DEV-004+008 两条上、给事件流加后处理开关"的打地鼠循环。8 类开关里 5 负向、3 无效/+1 动作，该模式已被证伪。
- 任何新想法先过第 0 步的 12 条集，再谈是否进入默认路径。

## 7. 与既有文档的关系

- 数据集划分与泄漏防护：沿用《视频动作识别优化实施计划》§16。
- 验收指标（slot ≥98% / shape ≥97% / target ≥97% / clear ≥98% / 单格 ≥99.5% 等）：沿用同文档 §19；本方案主张在"动作数正确"条件下分层报告这些指标。
- 多解与待复核规则：沿用同文档 §8 与《验收标准》第 6 条。
- 实验记录：继续维护在 `docs/recognition/optimization-experiments.md`；本方案定义的是"改什么、按什么顺序"，实验记录负责"每一步的实测数据"。

# 附录 A：第 1 步改造切口评估（代码级，2026-07-23）

> 本附录是把 §3.2「托盘优先重构」落到 `timeline_analyzer.py` 具体行号的可行性评估，基于对事件诞生主干、托盘形状链路、槽位/拾取链路的通读。行号为评估时的大致位置，实现时以实际为准。

## A.1 结论先行

- **性质是"翻开关 + 强化托盘基础读取器"，不是重写。** 系统的"黄金路径"本来就是"托盘形状 → 穷举合法落点 → 精确规则模拟"（`_find_move`+`_simulate`，唯一解即 `confidence: verified` / `exact_rule_simulation`）。托盘不是缺失的能力，而是被降级成了"佐证"。
- **拾取驱动的补事件通路也已经写好**，只是对彩色路径 `color_block_v1` 显式关闭。
- **风险集中在 2–3 处**；其中"召回修复"风险最高，必须走复核闸门、不得自动接受。
- **一个重要边界**：托盘优先能修 **shape / sourceSlot**，但**修不了落点 target**——target 只能靠棋盘侧的 motion-diff 求出。棋盘感知对 target/clear 仍然关键，不能"去棋盘"。

## A.2 事件诞生的真相（为什么会卡）

- 采样帧合并成稳定态,**仅按占用相等合并**（`_occupancy` 只看 `cell is not None`，不看颜色/hue）；短于 `min_stable_frames ≈ 0.13s` 的 run 被当动画噪声丢弃。
- 主循环对每个 `before` 稳定态,在 ≤6 态 / ≤2.2s 窗口内找一个"能被唯一合法 move 解释"的 `after`。三条出口：**verified（唯一解）/ reverse_clear / 板差兜底**。板差兜底硬性要求"棋盘有新增格"（`if added`），形状取原始 added-cells。
- **纯消除、或落子即消导致净占用回到原样、或材质噪声使占用矩阵不变 → 主干根本不产生 event。** 这是召回洞的确切位置。
- `slotActivity` 在诞生阶段**完全不被读取**；`slot_pickups` 在主循环**之后**才计算,只做"贴附"（补 sourceSlot/shape/时间到已存在事件）或三条受严格闸门的"回填"。
- **所有后处理一律"只删 / 只并"**：`_filter_cancelled_drags`（删）、`_filter_low_quality_tail_candidates`（删）、`_collapse_drag_windows`（多→一）、`_coalesce_action_fragments`（并）、`_apply_fsm_event_constraints`（删）、`_filter_color_clear_cooldown_fragments`（删）。**没有任何一个能把漏掉的动作补回来**——这从结构上解释了为什么过去所有后处理开关都动不了召回。

## A.3 三个漏点（精确到行）

| 漏点 | 位置 | 机制 |
|---|---|---|
| **形状** | 板差兜底 `~3193-3295`；`~3508` `source_has_extra_edge_cells` | `_find_move` 返回 0/多解时用原始 added-cells 当形状；证据附加阶段甚至主动用板差覆盖托盘真值（落子即消时板差恰恰是残影） |
| **召回** | 事件绑定棋盘稳定态 `~3020/~3036`；拾取补事件 `~3690-3770` 对 color 关闭于 `~3681` | 没形成独立稳定态的动作不诞生；唯一的"无棋盘差也能生事件"通路（coverage_gap 回填）对彩色路径被排除 |
| **测量** | —— | 已在第 0 步（`truth_benchmark` 检测/识别解耦）解决 |

## A.4 总开关：`_bottom_groups` 的拆格质量

- `_bottom_groups`（托盘逐帧基础读取器）是**最弱环**：**无自评分、无连通校验**；同色相连块的拆格**只押一个假设**——每格 ≈ 0.42×板格 pitch + 包围盒等分 + 每格覆盖率 ≥0.16，**完全没用内部边缘 / 亮度周期 / 角点 / 阴影**。3 槽、板宽三等分、0.42、0.16 全部写死。
- 这正好命中 **DEV-004（粉色大全消）、DEV-008（双 L 连消）** 这些同色相连块样本。
- 托盘链路里**更成熟的识别器是存在的**,但被设成高门槛的"有条件覆盖"：`_source_slot_material_consensus`（多帧逐格色相投票,score=support/usable∈(0.55,1]，需 support≥3，且有"件确已离开托盘"守卫）、`_repeated_round_element_shape`（霍夫圆，需 score≥0.82，主题圆形件专用）、`_grid_shape_from_mask`（差分掩码网格拟合，需 score≥0.38）。
- **托盘形状越准 → `_find_move` 唯一合法解越多 → `verified` 越多 → 板差兜底越少。** 一个改动同时抬升 shape 精度与召回（更多唯一解意味着更多动作被"验证性诞生"）。

## A.5 可复用清单（已有,不用造）

- **黄金路径**：`_find_move` + `_simulate` + `exact_rule_simulation`（唯一解自动验证）。
- **多帧共识去噪**：`_source_slot_material_consensus`（逐格投票 + 已离开守卫）、`_group_candidates`（保留所有 count≥3 签名的多假设,过滤单帧拖拽碎片）。
- **拾取补事件通路**：coverage_gap 回填 `~3690-3770`、开局 clear、大 clear 后；`_pickup_remains_consumed` 确认"真消耗"。
- **人机协同底座**：板差兜底事件已标 `confidence: candidate` + `board_delta_requires_confirmation`，并把托盘候选解保留在 `candidateSolutions` 里待复核——"高置信自动、低置信转复核"的数据结构现成。

## A.6 改造切口（按 ROI×风险 排序）

- **C1 强化 `_bottom_groups`【总开关，低风险】**：加自评分 + 连通校验 + pitch 之外的拆格信号（内部边缘 / 亮度周期）。必须**像素驱动**，不靠文件名（现有 image_block 纹理分支靠 `infer_material_profile` 文件名关键词,且不在 pickup 路径生效,对 color 路径无用）。它只改善喂给"已被规则验证的路径"的词表,风险最低、收益最广。
- **C2 翻转形状优先级【中风险】**：`~3508` 不再用板差覆盖高置信托盘形状；`_find_move` 失败时优先采用干净的托盘形状,仍不确定则转复核,而不是默默用 added-cells。
- **C3 打开彩色路径的拾取补事件【召回，高风险】**：调整 `~3681` 的 `color_block_v1` 排除；把 `_has_pickup_coverage_gap` 的**全局比值门**（`pickup_count ≥ max(12, event_count×1.55)`）换成**逐槽对账**（某槽一次消耗没有对应动作 → 生成一个复核候选）。
- **C4 补"上升沿"检测【C3 的使能件】**：现在只检测槽的"下降沿（拾取）"和"保持空（消耗）",**从不检测"槽被重新填充"**。补上刷新检测,才能把"空↔刷新"配对、按轮次对账,让 C3 逐槽稳健。

## A.7 风险与缓解

- **DEV-004 碎片化**：C3（更多拾取生事件）正是历史上 `gap_fill` 增假动作的地方。缓解：拾取生成的事件**一律 `confidence: candidate` + 规则模拟闸门 + 转复核,绝不自动接受**；用逐槽"一次消耗 = 一个动作"对账替代全局比值。后处理都是只删/只并,不会再把它拆开。
- **落点仍依赖棋盘**：托盘优先修 shape/slot,**不修 target**（target 靠 `_pickup_target` 的 motion-diff）。棋盘占用感知对 target/clear 仍关键。
- **color vs image 分叉**：`infer_material_profile` 靠文件名；C1 必须像素驱动才对 color 路径有效。
- **低分辨率（T05/DEV-005 类）**：全链无专门分支,阈值写死；C1 的阈值必须随 pitch 缩放并在低分辨率样本单独验证。
- **占用合并忽略颜色**：纯换色动作对稳定态切分不可见（`_occupancy` 只看占用）——玩法中罕见,但在"换色变体回归"时需注意。
- **不变量**：`exact_rule_simulation` 始终是**唯一的自动接受判据**,其余全部 candidate → 复核。

## A.8 分阶段建议

1. **P1 测量**：用第 0 步报表在 12 条调优集上跑出「`verified` 率 vs `candidate` 率」的分场景分布,先量化"shape 洞多大、recall 洞多大",再决定 C1–C4 的投入配比。
2. **P2 总开关（低风险）**：实现 C1,测 `verified` 率抬升与 shape 精度。
3. **P3 形状优先级**：实现 C2,规则模拟闸门,歧义转复核。
4. **P4 召回（高风险）**：实现 C3+C4,逐槽对账,全部作为复核候选。
5. 每阶段独立开关 + 12 条调优集验证；**DEV-004 不碎片化**为硬门槛。
