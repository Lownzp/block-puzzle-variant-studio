# 托盘专项真值与逐槽评测设计（最小切片版）

> 本文档是《识别架构改造方案》第 1 步「托盘优先重构」的配套地基：为托盘形状识别（`_bottom_groups`）建立 **component 级**真值与评测，回答"短板样本到底是托盘没检出、还是拆错"。设计经 2026-07-23 brainstorming 对齐，范围刻意收敛为最小验证切片。

## 1. 背景与目标

- C1（`tray_shape_grid_refine_v1`）在 8 条彩色回归集上 A/B **指标完全不变、零回归**：连通修复触发了、score 产出了，但没有改变最终动作。
- 原因两层：① score 目前无下游消费者（等 C2）；② **短板样本 DEV-003/008/011 根本没产出托盘 score**——它们的问题是"托盘没被看到"，不是"拆格不连通"。
- 更关键：只有**动作级**真值，没有**托盘帧级**真值，所以动作级 `shapeAccuracy` 测不出 `_bottom_groups` 本身好坏（改动被下游棋盘仲裁吸收）。
- **目标**：建立托盘帧级真值 + 逐槽评测，直接测"每个槽有没有检出 / 形状对不对"，判定 DEV-008 短板的真正入口。

## 2. 范围（YAGNI）

**做**：

- 3 条视频：**DEV-008**（短板，主查）、**DEV-004**（已知好，正对照）、**DEV-011**（也没出 score，验证普遍性）。
- 真值"跟着已有动作走"：在每个动作**落子前**那一帧，标注三个槽各自的形状。
- 一个**嵌入现有复核界面**的标注 UI（复用现成的格子编辑器）。
- 一个**逐槽评测脚本** + 纯逻辑单测。

**不做**（本切片明确排除）：

- 不标注噪点、细缝、遮挡、拾取前后多状态（只标"落子前"单帧的三槽形状）。
- 不做独立的托盘标注页/模式（嵌进现有每步编辑器即可）。
- 不动休眠的 vis-timeline；不重做棋盘落点/涂格逻辑。
- 不扩到 8 条或全库；验证有用再谈扩量。

## 3. 标注 UI 设计

### 3.1 位置与交互

在现有复核界面（`renderAnnotationStudio` 注入 `#analysisResult`）的**每步编辑器 `workbenchHtml`** 内，新增一块"落子前托盘"面板，位于现有"方块形状 / 落点 / 消除"之后：

- 三个槽并排（左 / 中 / 右），每槽含：
  - 一个"有 / 空"分段开关（复用现成 `segmentHtml()`）；
  - 一个小格子网格，"有"时可点选、"空"时禁用并清空。
- 格子网格**复用现成的形状编辑器**：`shapeGrid()`（index.html:736）的渲染模式 + `.shape-grid/.shape-cell` 样式（index.html:40-42）+ `toggleActionCell()`（annotation-studio.js:1405）的"点选 → `[{row,col}]` 归一化数组"读写逻辑。三槽挂三个独立 shape，参照现成的"一对象挂多 shape"范式 `referenceShapeGrid()`（annotation-studio.js:562）。
- 选中某步时，现有 Video.js 播放器定位到该步"落子前"时间（复用 `selectAnnotationStep`），标注员对着画面点格子。**不需要单独的抽帧导图脚本。**
- 图标用 Lucide，注入后调 `refreshIcons()`；局部重渲用 `refreshWorkbench()`；撤销用 `recordAnnotationHistory()`。风格沿用 `annotation-studio.css`。

## 4. 真值数据结构

每个动作（复核界面的 action）新增一个字段 `trayBefore`：

```json
"trayBefore": {
  "frameIndex": 152,
  "slots": [
    { "slot": 0, "occupied": true,  "shape": [{"row":0,"col":0},{"row":0,"col":1},{"row":1,"col":0}] },
    { "slot": 1, "occupied": false, "shape": [] },
    { "slot": 2, "occupied": true,  "shape": [{"row":0,"col":0},{"row":1,"col":0},{"row":1,"col":1}] }
  ]
}
```

- `frameIndex`：标注时播放器定位、标注员确认的那一帧（评测脚本据此读帧）。
- `slots`：**恰好 3 个**，顺序即 slot 0/1/2；`occupied=false` 时 `shape` 为空数组。
- `shape`：格子坐标数组，归一化到左上角原点（与现有 `action.shape` 同构，不含 hue）。

**落盘**：随现有"保存复核"走 `POST /api/video/confirm-actions`（body 的 `actions` 数组原样携带 `trayBefore`）。后端若未原样保存未知字段，则在 confirm 处理里放行该字段（预计 ≤ 数行）。真值落在现有任务目录，不入库。

## 5. 逐槽评测脚本

`scripts/evaluate_tray_recognition.py`（新增，入库）。

**输入**：一个或多个已标注 `trayBefore` 的任务真值 + 对应视频；棋盘 `board/grid` 从任务真值读取。

**每个标注样本**（= 一个动作的 `trayBefore`）：按 `frameIndex` 用 cv2 读帧，分别以 `refine_grid=False` 与 `True` 调 `_bottom_groups(frame, board, rows, cols, refine_grid=...)`，逐槽与真值比对。

**逐槽判定**：

| 真值槽 | 程序输出 | 记为 |
|---|---|---|
| 有料 | 非 None | 检出（再比 shape：完全一致 = 形状正确） |
| 有料 | None | 漏检 |
| 空 | 非 None | 误检 |
| 空 | None | 正确 |

**指标（baseline vs refine 两列）**：

- `slotDetectionRate` = 检出的有料槽 / 全部有料槽
- `slotShapeExactRate` = 形状完全一致 / 检出的有料槽
- `falseSlotRate` = 误检槽 / 全部空槽
- refine 专项：连通修复触发次数、`score` 分布（min/中位/max）
- **交叉表**：每个动作的 `sourceSlot` 槽——「动作级是否漏检 × 该槽托盘是否检出」。动作级漏检信息若提供动作级预测目录则自动关联；否则输出"每动作 sourceSlot 槽检出/形状"列，供与动作级 `missed` 列表人工对照。

**输出**：机器可读 JSON + 人读 Markdown 摘要（分样本 + 汇总）。

## 6. 测试策略

- **评测脚本纯逻辑**（逐槽判定、指标聚合、交叉表）抽成纯函数，用合成数据单测（不需要视频/cv2），置于 `tests/`。
- **形状比对**须对"归一化后完全一致"鲁棒（顺序无关）。
- **前端交互**：项目前端无自动化测试，按 AGENTS.md 在浏览器手动验证：三槽网格对齐、有/空切换、点选写入 `trayBefore`、选步定位画面、动态重渲后图标刷新、保存后重载不丢。

## 8. 成功标准

- 3 条视频完成落子前三槽标注。
- 评测脚本跑出逐槽指标 + 交叉表。
- **能明确判定 DEV-008 短板入口**：是"托盘没检出"（`slotDetectionRate` 低）还是"托盘拆错"（检出但 `slotShapeExactRate` 低），并看出这与动作级漏检的关系。
- refine 对逐槽指标的真实增量首次可量化。

## 9. 标注规范（约定）

- **一帧只标"落子前"**：该动作方块尚未离开托盘、三槽最清晰的稳定帧。
- **有料 vs 空**：槽里有方块=有料并点出格形；已被拾取/尚未出块=空。
- **同色相连块**：按肉眼可分的实际格数点满（这正是要考验 `_bottom_groups` 的地方，真值以人眼为准）。
- **形状归一化**：编辑器自动把点选的格子归一化到左上角，标注员无需手动对齐。

## 10. 风险与未决（实现时确认）

- confirm-actions 是否原样保存 action 的额外字段——实现首步先验证，不行则后端放行。
- "落子前"帧的选取：默认取该步 `timeRanges.before.end` 附近；标注员可在播放器微调，最终以 `trayBefore.frameIndex`（标注员确认帧）为准。
- 评测脚本读 `board/grid` 的来源字段以任务真值实际结构为准（实现时核对）。
